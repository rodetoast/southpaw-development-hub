# 공통 개발 지침

- 기존 기능과 개발 이력을 읽고 요청을 해결하는 범위만 수정합니다. 관련 없는 리팩터링, 관성적인 전체 시험과 중간 지시 교환을 피합니다. 승인 범위에서 기술 문제를 해결하고 관련 검증, 문서화, 안전한 Git 반영까지 진행합니다.
- 코드와 조건이 같은 시험 결과는 재사용합니다. 실제 실행, 기존 보고서에서 재사용한 결과, 미검증을 구분합니다.
- 프로젝트의 미커밋 내용을 보존하고 검토된 개발 브랜치에 관련 변경만 정상 커밋과 push로 남깁니다. 기존 프로젝트 상세 규칙을 함께 적용합니다. 지시가 충돌하면 우선순위와 작업 승인 범위를 확인합니다.
- 회사 공식 심볼과 앱 아이콘을 구분합니다. UI 변경은 실제 Windows에서 관련 DPI, 테마, 좁은 창과 주요 동작을 가능한 범위에서 확인합니다.
- 작업 파일, 설정, 설치 상태, 외부 호스트 계약과 기존 app_id를 보존합니다. 기존 직원에게는 현재 바로가기와 업데이트 버튼을 유지합니다.
- 서명, 해시, 신뢰 바인딩, 카탈로그 순번과 복구 보호를 유지합니다. 운영 게시, 저장소 소유권 변경, 실제 직원 환경 변경은 해당 범위의 승인을 확인합니다.
- 완료 기록에 소스 커밋, 구현, 검증·미검증, 버전, 배포 상태 및 후속 작업을 남깁니다. 의미 있는 변경만 중앙 요약에 반영합니다. 공개 범위에 맞춰 직원 자료, 경로, 개인키·토큰을 제외합니다.

## 디자인 시안과 구현 검토 자료

- 각 프로그램의 소스 저장소에서 기존 자료 구조를 우선 사용합니다. 정해진 위치가 없으면 사용자가 제공한 자료나 GPT 시안은 `docs/design-references/`에, 실제 구현 화면·변경 전후 비교·동작 검증은 `docs/ui-reviews/`에 둡니다. 시안과 실행 결과의 종류를 명시합니다.
- 의미 있는 UI 또는 시각 기능 변경마다 결과를 설명할 최소한의 자료를 남깁니다. 화면 캡처 외에도 픽셀 이펙트, 애니메이션, 이미지 처리 결과, 타임라인 동작 등 기능에 맞는 형식을 씁니다. 움직임이 핵심이면 짧은 GIF나 영상을 사용합니다.
- 자동 촬영이 가능하면 Codex가 실제 구현을 직접 촬영합니다. 이미 같은 화면 상태를 입증하는 자료를 재사용하고, 비교가 필요할 때만 변경 전후의 대표 자료를 보존합니다.
- 갤러리 설명에 자료의 종류, 촬영하거나 검토한 버전, 구현 소스 커밋과 화면 상태를 기록합니다. 시안은 제공 출처를 기록하고 빌드 검증 근거로 사용하지 않습니다. 공개 가능한 자료만 커밋하며, 직원 정보·인증 정보·비공개 게임 자료와 사용자 경로가 화면이나 영상에 노출되지 않는지 확인합니다.
- 완료 보고에는 GitHub 갤러리 URL과 대표 이미지 또는 동작 자료의 **커밋 고정 직접 URL**을 함께 제공합니다. 의미 있는 변경은 프로젝트 상태 문서에도 갤러리를 연결합니다.
- 다른 프로그램에 참고가 되는 갤러리와 대표 자료는 중앙 허브의 기존 `projects/<project>.md` 요약에서 링크합니다. 중요한 시각 디자인 결정은 [결정 기록](DECISIONS.md)에 남깁니다. 중앙에는 링크를 관리하고 파일은 프로젝트 저장소에 둡니다. 통합 참조 파일을 재생성하면 결정 기록과 프로젝트 요약에 있는 대표 링크가 포함됩니다.

### GPT 검토용 PNG 만들기

- 의미 있는 UI 또는 시각 기능 변경을 마칠 때, 이미 보관한 대표 화면에서 GPT 첨부용 합본 PNG를 Codex가 생성합니다. 화면마다 제목과 상태(예: 변경 전후, 테마, DPI, 실행 조건)를 적고 합본 제목에는 프로젝트와 버전 또는 커밋을 넣습니다.
- 원본 화면을 축소하거나 잘라 맞추지 않습니다. 한 장이 너무 커지면 번호가 붙은 PNG 여러 장으로 나누고, 원본 화면 하나가 기준보다 크면 원본 해상도로 별도 페이지에 둡니다. 영상이 필요한 경우에는 갤러리의 원본 링크도 함께 제공합니다.
- 완료 보고에 GitHub 갤러리와 커밋 고정 대표 자료 링크, 생성된 합본의 로컬 경로를 함께 남깁니다. 합본은 첨부용으로 두고 기존 GitHub 원본과 갤러리를 유지합니다. 웹 ChatGPT가 링크를 열지 못하면 [AI 시작 안내](AI_START_HERE.md)의 검토 순서에 따라 실제 화면 확인이 필요한 경우에만 합본을 첨부합니다.

허브 루트에서 Python과 Pillow 10.1 이상으로 [합본 스크립트](../tools/make_review_sheet.py)를 실행합니다. 화면마다 `--view`에 기존 이미지 경로, 화면 제목, 상태를 순서대로 지정합니다. 아래 예시의 경로는 실제 검토 파일과 출력 위치로 바꿉니다.

```powershell
python tools/make_review_sheet.py --title "프로젝트 / v1.2.3" --output "C:/Dev/reviews/project-v1.2.3.png" --view "C:/Dev/reviews/before.png" "작업 화면" "변경 전 · 다크 · 100%" --view "C:/Dev/reviews/after.png" "작업 화면" "변경 후 · 다크 · 100%"
```

Windows에서는 기본 한글 폰트를 사용합니다. 다른 환경에서 한글 제목이 필요하면 `--font`에 사용할 한글 폰트 파일을 지정합니다.

## GitHub 개발 인증 및 중앙 허브 갱신

- 개발 작업에는 기존 `rodetoast` 인증을 우선 사용합니다. `gh auth status`와 `gh api user --jq .login`으로 CLI 계정을 확인합니다. Git의 커밋 작성자 이름·이메일과 CLI의 로그인 계정만으로 실제 Git push 계정을 판단하지 않습니다.
- PS2ASE 0.3.7 인계에서는 기본 Git HTTPS helper가 `toast-source`를 선택했습니다. 이 계정은 PS2ASE에 쓸 수 있었지만 중앙 허브에는 읽기만 가능해 HTTP 403이 발생했습니다. 다른 개발 저장소에서도 같은 helper 경로를 확인했습니다.
- 여러 계정이 있는 환경에서는 기존 인증을 유지하고, 아래처럼 **현재 대상 저장소의 정확한 HTTPS push URL에 한해서** GitHub CLI helper를 사용합니다. 운영 배포 도구에는 이 개발 명령을 적용하지 않습니다.

### Windows PowerShell 예시

허브 작업 사본에서 GitHub CLI가 PATH에 있는 상태로 실행합니다. 이미 설치된 실행 파일이 PATH에 없다면 해당 세션에서만 찾을 수 있게 설정합니다. 먼저 실제 GitHub push URL과 `gh api user --jq .login`의 결과가 각각 의도한 저장소와 `rodetoast`인지 확인합니다.

```powershell
$target = git remote get-url --push origin
$key = "credential.$target"
git -c "$key.helper=" -c "$key.helper=!gh auth git-credential" -c "$key.username=rodetoast" push --dry-run origin HEAD:refs/heads/main
```

허브에서 최신 `origin/main`과 정상 fast-forward 관계이고 dry-run이 통과하면 같은 명령에서 `--dry-run`을 빼고 문서 변경을 반영합니다. 제품 소스 작업에서는 그 저장소의 검토된 개발 브랜치로 대상을 바꿉니다. 보호 정책이 PR을 요구하면 해당 절차를 따릅니다. Dry-run은 원격 브랜치를 바꾸지 않으며 모든 서버 측 보호 규칙 통과를 보장하지 않습니다.

### HTTP 403이 발생하면

1. CLI를 덮어쓸 수 있는 `GH_TOKEN`·`GITHUB_TOKEN`의 **존재만** 확인합니다. 실제 push URL과 fetch URL, URL 치환, HTTPS helper의 적용 범위 및 `credential.useHttpPath`를 확인합니다.
2. 선택된 인증의 저장소 쓰기 권한, 토큰 권한 범위, 브랜치 보호 및 Ruleset을 확인합니다. 자격 증명과 토큰을 화면이나 로그에 출력하지 않습니다. 확인할 수 없는 권한은 미확인으로 남깁니다.
3. 쓰기가 막히면 검토한 문서 커밋과 패치를 안전한 로컬 위치에 보존합니다. 최신 원격 기준, 로컬 커밋, 충돌과 미반영 범위를 인계합니다. 원격에서 문서를 확인한 뒤에만 동기화 완료로 기록합니다.
