# 새 개발 작업 시작

1. [공통 개발 지침](DEVELOPMENT_RULES.md)을 읽습니다. 패키징·배포 작업에서는 [배포 절차](RELEASE_GUIDE.md)도 읽습니다.
2. [프로젝트 목록](PROJECTS.md)에서 해당 프로그램의 상태 문서와 개발 브랜치를 엽니다. 저장소의 AGENTS.md, Git 상태, HEAD, 원격 주소와 관련 설계·검증 기록을 확인합니다.
3. Codex 지시에는 목표, 보존할 기능과 데이터, 변경 관련 검증, 배포 승인 경계, 완료 시 갱신할 문서를 포함합니다.
4. 결과를 실제 커밋, 시험 증거, 운영 아티팩트와 비교합니다. 상태 문서가 다르면 확인한 코드·Git·서명 배포 근거에 맞게 문서를 바로잡습니다. 확인된 사실, 기존 보고서와 미검증 상태를 구분합니다.

프로그램 지칭은 [개발 관리 번호](PROJECTS.md#개발-관리-번호)를 따릅니다. 사용자가 번호로 지칭하면 GPT는 답변 및 Codex 지시에 해당 번호와 프로그램 명칭을 함께 표시합니다. Southpaw Tools Launcher는 번호 없이 런처 개발 및 종합 관리감독을 담당합니다.

검증 목적과 실제 실행 환경을 먼저 판단하고 [개발 환경과 독립 검증](DEVELOPMENT_RULES.md#개발-환경과-독립-검증)에 따라 개발 PC 또는 별도 테스트 PC를 선택합니다. 테스트 PC 이용과 빌드는 필수 단계가 아니며, 필요한 호스트·라이선스·권한과 데이터 보호 조건을 확인합니다.

작업을 시작할 때 [프로젝트 간 협업 규칙](COLLABORATION.md)의 프로젝트 라벨에서 현재 프로젝트의 열린 안건만 확인합니다.

## 개발 허브와 시각 자료 열기

- GitHub 연결이 가능한 환경에서는 해당 계정의 실제 저장소 접근 권한을 확인하고 최신 원문, 개발 브랜치와 소스, 커밋 고정 검토 자료를 직접 참조합니다. 연결만으로 모든 저장소나 파일 형식에 접근할 수 있다고 단정하지 않습니다.
- 연결되지 않은 환경에서도 공개 GitHub URL, [Markdown 원문](https://raw.githubusercontent.com/rodetoast/southpaw-development-hub/main/docs/AI_START_HERE.md) 또는 실행 환경에서 지원하는 공개 Git clone을 사용할 수 있습니다. 공개 여부와 실제 도구의 열람 가능 여부는 구분합니다. 계정 연결을 일률적으로 요구하지 않습니다.
- 2026-11-25 개인 ChatGPT 계정에서 GitHub 연결 후 PS2ASE와 중앙 허브의 최신 문서·개발 브랜치·Python 소스 및 PNG 이미지 직접 열람과 시각 분석에 성공했다는 사용자 검증 보고가 있었습니다. 이는 해당 환경의 결과이며 다른 계정이나 도구에도 동일하게 적용된다는 보장은 없습니다.

AGENTS.md는 읽기 절차의 진입점입니다. 링크를 적는 것만으로 원격 문서가 자동 로드되지는 않습니다. 접근이 실패하면 읽지 못한 범위를 남기고 접근 가능한 지침으로 진행합니다. 웹 ChatGPT의 기획·UX·개발 결과 검토에는 이 페이지를 공통 시작 링크로 사용합니다. 최신 원문을 읽을 수 없는 경우 [통합 참조 파일](../SOUTHPAW_AI_CONTEXT.md)을 사용하고 기준 커밋과 확인일을 확인합니다. 실제 코드 및 최신 Codex 검증 결과를 스냅샷보다 우선합니다. GitHub에 변경을 올리려면 별도의 적절한 쓰기 권한과 작업 승인이 필요합니다.

UI나 시각적 기능 검토는 [시각 자료 공유 규칙](DEVELOPMENT_RULES.md#디자인-시안과-구현-검토-자료)을 따릅니다. GitHub 갤러리와 커밋 고정 원본을 실제로 열람할 수 있으면 직접 참조하고, 이미지 픽셀을 확인한 평가와 보고서·텍스트만 읽은 판단을 구분합니다. 직접 열람이 불가능하고 실제 화면 확인이 필요한 경우에만 GPT 검토용 합본 PNG를 요청합니다. 과거 비연결 웹 수집 환경에서 GitHub 일반 주소, Raw, API, CDN, Pages 접근 실패가 반복됐으므로 같은 조건에서 불필요한 재시험이나 원인 분석을 반복하지 않습니다. 계정 연결이나 접근 환경이 달라지면 대표 자료로 접근 가능 여부를 확인할 수 있습니다. 개발 보고서로 판단 가능한 내용은 먼저 검토합니다.

모든 프로그램에서 구현에 활용할 GPT 시안은 사용자 승인 및 실제 GitHub 쓰기 접근이 가능한 경우 [GPT 디자인 시안 직접 공유 규칙](DEVELOPMENT_RULES.md#gpt-디자인-시안-직접-공유)에 따라 해당 프로그램의 디자인 참고 자료 경로에 직접 등록하고 Codex에 커밋 고정 자료를 전달하는 방식을 우선합니다. 제품 코드 및 배포 영역은 이 절차에서 변경하지 않습니다. 직접 등록할 수 없으면 전달 가능한 파일을 제공하고 Codex가 등록하는 기존 방식을 사용합니다. GitHub 연결만으로 모든 파일 형식의 업로드, 계정 간 권한 공유 또는 자동 작업 전달이 보장된다고 가정하지 않습니다.

## 완료 시 기록

의미 있는 변경은 소스 저장소 `docs/PROJECT_STATUS.md`를 먼저 갱신하고, 같은 작업에서 허브의 프로젝트 요약과 목록도 영향받는 범위만 갱신합니다. 상세 근거는 프로젝트 저장소에 남깁니다. 중앙 쓰기 권한이 없으면 패치를 준비하고 동기화 대기라고 보고합니다. 작업을 수행하는 Codex가 실행하는 절차이며 백그라운드 동기화는 없습니다.
